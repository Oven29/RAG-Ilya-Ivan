# Требования к эргономике и технической эстетике интерфейсов

## Описание

Подраздел «Требования к эргономике и технической эстетике» (п. 4.1.4 ГОСТ 34.602-2020) устанавливает критерии удобства использования (Usability), доступности (Accessibility), наглядности и эффективности взаимодействия конечного пользователя с автоматизированной системой. Качественный пользовательский интерфейс (UI/UX) снижает вероятность ошибок оператора, сокращает время обучения персонала и повышает общую производительность труда.

Требования к интерфейсам охватывают:
1. **Согласованность и единообразие (Consistency)**: использование единой дизайн-системы, общих стилей элементов управления, цветовой палитры, типографики и расположения навигационных блоков на всех экранах системы.
2. **Информативность и обратная связь**: система должна незамедлительно реагировать на действия пользователя (индикаторы загрузки, прогресс-бары, всплывающие уведомления о статусе операций).
3. **Защита от ошибочных действий пользователя**: подтверждение деструктивных операций (удаление, отмена транзакции), блокировка повторных кликов, валидация полей ввода «на лету» с понятными подсказками на русском языке.
4. **Доступность (Accessibility / WCAG 2.1)**: поддержка контрастности текста, навигация с клавиатуры без использования мыши, совместимость с программами экранного доступа для слабовидящих.
5. **Временные характеристики взаимодействия**: время реакции интерфейса на единичное действие оператора не должно превышать эргономических стандартов (до 0.1–0.5 с).

## Когда применять

- При проектировании автоматизированных рабочих мест (АРМ) операторов, диспетчеров и офисных сотрудников.
- При разработке публичных пользовательских веб-порталов и мобильных приложений.
- В системах критического контроля, где ошибки оператора могут привести к авариям.
- Для выполнения требований стандартов доступности государственных информационных ресурсов.

## Признаки нарушения

- Разные экраны системы выполнены в разнородных стилях с несовпадающими шрифтами и цветовыми схемами.
- При длительных операциях (более 1 секунды) экран зависает, индикатор прогресса или спиннер загрузки отсутствует.
- Деструктивные операции (безвозвратное удаление записей) выполняются в один клик без диалога подтверждения.
- Сообщения об ошибках выводятся в виде системных стектрейсов или сырых кодов исключений на английском языке.
- Отсутствует адаптивность под разные разрешения экранов, интерфейс ломается при изменении масштаба браузера.
- Невозможно выполнить базовые сценарии ввода данных с использованием только клавиатуры.

## Примеры нарушений в ТЗ

- «Требования к дизайну интерфейса и удобству пользователя не предъявляются, разработчик создает UI по своему усмотрению.»
- «При возникновении ошибки на экране отображается сырой Java Stack Trace для удобства отладки.»
- «Интерфейс оптимизирован исключительно под разрешение 1920х1080, при других разрешениях отображение не тестируется.»
- «Подтверждение удаления учетных записей не требуется ради ускорения работы оператора.»

## Рекомендации

- Разработайте единый UI Kit / Дизайн-систему на базе современных компонентов (Material Design, Ant Design).
- Реализуйте обязательную индикацию длительных асинхронных процессов с блокировкой интерфейса от повторных нажатий.
- Все сообщения об ошибках формулируйте понятным языком с описанием причины проблемы и шагов по её устранению.
- Обеспечьте соблюдение стандарта ГОСТ Р 52872-2019 по доступности для людей с инвалидностью.
- В ТЗ фиксируйте предельное время отклика пользовательского интерфейса (например, «реакция на клик — не более 200 мс»).
