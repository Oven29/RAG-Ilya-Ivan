# Правила репозитория и кодинга для AI-агентов (SDD)

Данный репозиторий разрабатывается по методологии **Spec-Driven Development (SDD)** в рамках курса НИРС 2026 (МГТУ им. Н.Э. Баумана).

## 1. Порядок внесения любых изменений
Перед изменением любого кода агент или разработчик ОБЯЗАН:
1. Ознакомиться со спецификациями продукта в `spec/product/` (`product.md`, `scenarios.md`).
2. Ознакомиться с техническими спецификациями в `spec/tech/` (`architecture.md`, `rag.md`, `quality.md`).
3. При изменении требований сначала обновить соответствующий файл спецификации.
4. Выполнить проверку тестов (`pytest tests/`) и бенчмарка (`python -m benchmark.run`).
5. Зафиксировать изменения в файле `CHANGE_HISTORY.md` с указанием даты, автора и затронутых компонентов.

## 2. Архитектурные ограничения
- **BM25 Search Core**: запрещено использовать внешние поисковые движки (Elasticsearch, Whoosh, rank_bm25). Алгоритм Okapi BM25 должен быть реализован строго в файле `app/rag/bm25.py` по формулам методички кафедры ИУ5.
- **LLM Client**: использовать стандартную библиотеку Python (`urllib.request`) без сторонних тяжелых библиотек (LangChain, LlamaIndex запрещены).
- **Формат ответа RAG**: строго структурированный JSON с полями `violations`, `summary`, `sources`, `refused`, `refusal_reason`.
- **Защита от галлюцинаций**: список источников `sources` в ответе должен содержать ТОЛЬКО идентификаторы документов, реально найденных поисковиком (из множества `hits`).
- **Refusal (Отказ от ответа)**: при запросах, не относящихся к архитектуре ПО или ТЗ, система обязана возвращать `refused: true`.

## 3. Команда проекта
- **Иван Овчинников**: BM25 & RAG Core, Corpus, Backend API, Benchmark.
- **Илья**: Web UI, Docker/DevOps, Integration Tests, Documentation.
