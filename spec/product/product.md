# Описание продукта: RAG-валидатор архитектурных решений и ТЗ

## Название

**RAG-валидатор архитектурных решений и технических заданий**

## Целевая аудитория

| Группа | Контекст использования |
|---|---|
| Студенты технических специальностей | Проверка курсовых и дипломных ТЗ перед защитой |
| Junior-разработчики | Самопроверка архитектурных решений до code review |
| Тимлиды / техлиды | Быстрый первичный аудит документации команды |

## Проблема

Ручная проверка технических заданий и архитектурных решений на соответствие ГОСТам и best-practices:

- **Трудоёмка**: опытный специалист тратит 2–4 часа на один документ.
- **Ненадёжна**: часть нарушений неизбежно пропускается из-за усталости или незнания нормативов.
- **Дорога**: привлечение внешнего эксперта стоит денег, а внутренний ревьювер отвлекается от разработки.
- **Плохо масштабируется**: при росте команды количество документов растёт линейно, а ревьюверов — нет.

## Решение

RAG-система автоматической валидации, которая:

1. Принимает черновик ТЗ или текстовое описание архитектуры.
2. Выполняет семантический поиск по корпусу ГОСТов и архитектурных best-practices с помощью BM25.
3. Формирует промпт для LLM с найденными релевантными фрагментами.
4. Возвращает структурированный JSON: список нарушений, ссылки на источники, итоговое резюме.

**Ключевые свойства:**
- Работает полностью локально (нет отправки данных во внешние API, если LLM развёрнута локально).
- Прозрачность: каждое нарушение сопровождается ссылкой на конкретный документ и раздел корпуса.
- Быстродействие: ответ за ≤ 10 с на среднестатистическом запросе.

## Границы системы (Scope)

### В scope
- Проверка на соответствие архитектурным паттернам из корпуса (data/corpus/*.md).
- Проверка на соответствие ГОСТам, включённым в корпус.
- Генерация списка нарушений с цитированием источников.
- Отказ (refusal) на вопросы вне предметной области.

### Вне scope
- Юридические советы и правовые заключения.
- Проверка орфографии и стилистики текста.
- Автоматическое исправление обнаруженных нарушений.
- Поддержка языков, кроме русского и английского.
- Работа с бинарными форматами (.docx, .pdf) — только plaintext / Markdown.

## Технологический стек (кратко)

- **Backend**: Python 3.11, FastAPI, Jinja2
- **RAG**: BM25 (Okapi), Snowball-стеммер (русский), кастомный чанкер Markdown
- **LLM**: совместимый с OpenAI Chat Completions API (локальный или облачный)
- **Frontend**: HTML5 + vanilla JS (или лёгкий фреймворк)
- **Инфраструктура**: Docker, docker-compose
- **Качество**: ruff (линтер), pytest (тесты ≥ 70% coverage), CI-пайплайн
